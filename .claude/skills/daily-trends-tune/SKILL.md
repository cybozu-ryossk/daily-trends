# トレンドネタ収集プロファイルのチューニング

トレンドノート（保存先・ファイル名は `daily-trends/output-profile.md` が正本）でユーザーがチェック（`[x]`）した／しなかった履歴を興味シグナルとして分析し、`interests.md`（`daily-trends-collect` スキルディレクトリ内の収集プロファイル）の更新案を提示する。ユーザー確認後に適用する。

## 実行手順

### 1. データ収集

- `daily-trends/output-profile.md` を読み、保存先ディレクトリ・ファイル名規則を確認する
- 対象: 上記ディレクトリ配下の `*.md` ファイル。デフォルトは直近 30 日分（引数で日数指定可。例: `/trends-tune 60`）
- 各リスト行から抽出する: チェック状態（`[x]` / `[X]` = チェック済み）、カテゴリ（直前の `##` 見出し）、タイトル、URL（ドメインをソース推定に使う）、要約
- `## 詳細要約` に同一 URL の見出しがある記事は「深掘り済み」としてマークする（チェックより強い興味シグナル）
- 対象が 3 日分未満なら「データ不足のため提案なし」と報告して終了

### 2. 集計

- カテゴリ別: 掲載数・チェック数・チェック率・深掘り数
- ソース（ドメイン）別: 掲載数・チェック率
- テーマ抽出: チェック済み・深掘り済み記事のタイトル・要約から共通テーマを抽出する。既存の興味領域にないテーマは新規候補。掲載され続けてチェックゼロのテーマは抑制候補

### 3. 提案生成

現状の `../daily-trends-collect/interests.md` を読み込み、変更案を根拠（件数・チェック率）付きで作る。

- **興味領域**: 新テーマの追加（まず「監視中」または「上昇中」へ）、昇格（監視中 → 上昇中 → コア）、降格（コア → 収集抑制）
- **収集ソース**: チェック率が継続的に低いソース（目安: 掲載 5 件以上でチェック 0）の「除外・停止中」への移動、チェック済み記事に頻出する未収集ドメインの追加候補、上昇中テーマに合う新ソースの提案（必要なら Web 検索してよい）
- **カテゴリ粒度**: チェックが集中するカテゴリの細分化案、チェックゼロが続くカテゴリの統合案（「カテゴリ粒度メモ」への指示として書く）

**保守性ルール（急激に変えない）**:

- 1 回の実行での変更は各セクション 3 件程度まで
- コアからの直接削除はしない。まず「収集抑制」へ移動し、次回以降も変化がなければ削除を提案する
- 掲載 3 件未満のテーマ・ソースは降格判断の対象にしない（データ不足）
- ユーザーが手動編集した内容を無断で消さない

### 4. 確認と適用

1. 集計サマリを提示する: カテゴリ別チェック率・ソース別チェック率・過大／過小評価テーマ
2. 変更案を「変更前 → 変更後」が分かる形式で提示し、各変更に根拠を 1 行添える
3. ユーザーの確認を得てから `../daily-trends-collect/interests.md` へ適用する（確認前に書き換えない）
4. 適用時、interests.md の「## 更新履歴」に `- YYYY-MM-DD: 変更内容の要約（根拠）` を追記する

## 注意事項

- interests.md の文章は通常の日本語で書く
- チェック済みは `[x]`（`[X]` 許容）。リスト内の空白の揺れを許容してマッチする（`- [ x ]`、`-[x]` など）
- 「現状維持が妥当」という結論も許容する。無理に変更をひねり出さない
- 分析はローカルの trends ノートで完結する（新ソース探索時のみ Web 検索を使う）
- trends ノート以外のファイル（daily ノートのタスク等）のチェックボックスを集計に混ぜない
