# トレンドネタ詳細要約（出力レイヤー）

`/trends` が出力したトレンドネタのリストで、ユーザーがチェック（`[x]`）を付けた記事について、`daily-trends-detail-fetch` に本文取得・要約生成を依頼し、結果を同じノートの `## 詳細要約` セクションに追記する。本文取得方法・要約の書き方そのものは持たない（`daily-trends-detail-fetch` の責務）。

## 実行手順

### 1. 対象ファイルの特定

`daily-trends/output-profile.md` を読み、保存先ディレクトリ・ファイル名規則を確認する。

- 引数で日付（`YYYY-MM-DD`）が指定されていればそのファイル
- 指定がなければ当日のファイル
- ファイルが存在しない場合はその旨を報告して終了

### 2. チェック済み記事の抽出

ファイル内のリスト（`- [ ]` チェックボックス）から、`[x]`（`[X]` も許容）でチェックされた行を抽出し、タイトルと URL を取得する。

- リストアイテムは `- [x] [タイトル](URL)` の形式
- チェック状態の空白の揺れを許容してマッチする（`- [ x ]`、`-[x]` など）
- チェック済みが 0 件なら「チェック済み記事なし」と報告して終了

**冪等性**: 既に `## 詳細要約` セクションに同一 URL の `###` 見出しがある記事は request から除外する（再実行しても重複しない）。全件除外ならその旨を報告して終了。

### 3. 本文取得の依頼

除外後の対象を `output-profile.md` の中間ファイル作業ディレクトリに `trends-detail-request-YYYY-MM-DD.json`（`{title_ja, url}` の配列、`## 詳細要約` セクションでの想定出現順）として書き出し、`daily-trends-detail-fetch` スキルを起動する。

### 4. 書き込み

`daily-trends-detail-fetch` が出力した `trends-detail-YYYY-MM-DD.json` を読み、ファイル末尾（カテゴリ別リスト群の後）に書く：

- `## 詳細要約` セクションがなければ新設する
- 記事ごとに `### [日本語タイトル](URL)` の見出しで追記する。見出しのタイトル・URL はカテゴリ別リストのものと一致させる
- 並び順はカテゴリ別リストでの出現順（カテゴリ順→行順。手順 3 で書き出した順序と一致する）
- `bullets` を箇条書きで、最後に `- **業務への示唆**: {implication}` を追記する
- `fetch_status` が `fallback` または `note` が空でない場合は、箇条書きの末尾に `note` の内容を反映する

**フォーマット**:

```markdown
## 詳細要約

### [日本語タイトル](URL)

- 論点・事実 1
- 論点・事実 2
- 論点・事実 3
- 論点・事実 4
- 論点・事実 5
- **業務への示唆**: 業務文脈との接続を 1 行で

### [次の記事タイトル](URL)

...
```

書き込み後、処理した記事数・スキップした記事数（冪等性で除外・取得失敗）を報告する。

## 注意事項

- 見出し・要約の本文は通常の日本語で書く（圧縮口調にしない）
- カテゴリ別リスト側は変更しない（チェック状態・要約はそのまま）
- 1 回の実行でチェック済み全件を処理する（件数が多くても省略しない）
- **本文取得方法・要約生成ロジックは `daily-trends-detail-fetch` の責務**。このスキルはチェックボックス解釈・冪等性判定・ファイルへの追記のみを行う
